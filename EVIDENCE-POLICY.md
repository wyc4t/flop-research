# Evidence and publication policy

This repository contains selected public evidence and authored research. It is not a backup of an operator's computer or a complete export of project conversations.

## Labels

| Label | Meaning |
| --- | --- |
| Verified source | A specified primary source or public response was read on the stated date. |
| Recorded observation | A retained experiment records the result at a particular version/time; it may not describe the current deployment. |
| Reported | A participant or user supplied the claim; independent confirmation is absent or narrower. |
| Inference | Interpretation of evidence, with alternatives and limits. |
| Prepared | Draft, local patch or plan; publication/adoption is not established. |
| Unknown | Evidence is insufficient. Missing evidence is not evidence of failure, zero credit or misconduct. |

An issue comment, PR, local test pass, upstream merge and production deployment are separate milestones. A maintained public tool is separate from measured human use. GitHub search results are not a complete contribution census.

## Reproducibility

Preserve objective, hypothesis, exact method, code revision, time/timezone, exact messages or requests, relevant room/sequence/DID, raw outcomes, interpretation, limitations and the next useful test. Separate failed methodology from valid measurements. Use controls when they materially improve the conclusion. Signatures do not authenticate unsigned venue metadata.

For the miner report, public chain identifiers and receipts allow independent chain inspection. The report does not supply a runnable copy of the private operator setup, private evidence or an end-to-end receipt replay. Raw-amount fields are decimal strings; FLOP devnet observations here use 18 decimals.

## Identity and rewards

Different DIDs or wallet addresses do not establish independent people or systems. A protocol-shaped chain is not semantic task fulfillment. PaperRail is a rehearsal rail without real value. An indexed PAID channel does not establish answer correctness or eligible work credit. No personal allocation or guaranteed return is claimed.

## Scope and identifiers

The original workspace reused some experiment IDs. Index by **ID + date + topic**; retain original names for traceability. New catalog entries should use unique dated paths and avoid assigning an old ID to unrelated work. The catalog's dated claims should be updated through explicit corrections rather than silently replacing old observations.

## Publication boundary

Include only reviewed public records, necessary public identifiers, sanitized observations and reproducible findings. Exclude private keys, identity files, seeds, passphrases, bearer tokens, signed request URLs, credentials, recovery archives, private configuration, private messages, SSH endpoints and provider account/billing screenshots. Do not bulk-copy logs or the workspace. Public receipt signatures, when part of an existing experimental dataset, are distinct from private signing material.

Local hashes establish byte consistency, not a trusted timestamp, capture completeness, correct execution or independent ownership. A catalog entry describing local research is not a claim that its complete raw evidence is published here.
